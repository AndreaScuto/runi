## Protocol

- Ten deterministic JavaScript implementation tasks, each executed in a fresh disposable workspace.
- Every scenario ran first as one direct OpenCode operation and then as an OpenCode worker supervised by Runi.
- Both modes used the same OpenCode executable, pinned model, worker prompt, baseline check and hidden final acceptance verifier.
- Runs were serial. End-to-end time includes workspace preparation, baseline verification, worker execution and final verification.
- A result counts as successful only when the host-side hidden verifier exits with code 0.
- Runi had a maximum of three attempts and a five-minute wall-time budget per task.

## Interpretation

The measured savings are an observation from this paired sample, not proof that supervision intrinsically reduces model usage. Model responses are stochastic, direct always ran before Runi, and the largest differences came from `slugify` and `palindrome`. No retry was needed, so this run does not quantify Runi's recovery advantage. P95 was worse with Runi even though total, mean and median time were better.

The strongest result is correctness parity: both modes achieved 100% independently verified completion. A future longitudinal comparison should repeat the suite multiple times, alternate execution order and include fault-injection scenarios that exercise durable recovery.

```powershell
  --model opencode/mimo-v2.5-free `
  --count 10 `
  --max-attempts 3 `
  --wall-time 5m
```
